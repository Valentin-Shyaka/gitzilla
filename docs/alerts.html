alerts

Where gitzilla tells you, and how a whole team finds out within a minute.

When GitHub reports a push your Mac didn't sign, your Worker sends one alert to every channel you've set up. Each alert names the repo, branch, commits, time and flags. It never includes code.

Pusher: alice
Commits: 91aa0c4 → b07d3f1
Time: 2026-10-03 01:12:40 UTC / 03/10/2026, 03:12:40 (Africa/Kigali)

If this wasn't you: revoke tokens at https://github.com/settings/applications

Channels

phone push available

Through the free ntfy app on iOS or Android. The installer makes a random topic name and you subscribe to it. Red alerts arrive at urgent priority (5), orange at normal priority (3).

slack available

Any Slack channel you can add an incoming webhook to: your own DMs, a team channel, or an org-wide security channel. Optional; leave it empty at install and only the phone gets alerts.

phone call available

Red alerts also ring up to 5 phone numbers, so an on-call phone wakes up even on silent. Calls go through ntfy, which needs an ntfy Pro account with the numbers verified there. Calls are spoken in English. At most one call per number every 10 minutes, however many pushes arrive. Orange alerts never call.

Why a minute

t+0s    stolen token pushes to github
t+2s    github app webhook → your worker
t+~20s  no push note arrived → alert       # the worker waits 20 s for a late note
t+~25s  ntfy + slack deliver, phones ring # everyone subscribed sees it
t+5m    mac agent deep-checks, offers restore

The 3 Oct attack rewrote 67 branches in one run. The sooner someone sees the first push, the sooner the token gets revoked and the fewer repos, CI runs and downstream clones pick up the payload.

For teams and companies

A stolen developer credential is a company problem. If one person's token pushes malware, every teammate who pulls, every CI job and every deploy is exposed. An org gitzilla watches every repo the organization owns and tells the whole team, with the name of the account that pushed.

one worker

An admin runs ./install.sh --org acme. That deploys a separate Worker and a GitHub App installed on the organization, with its own ntfy topic, Slack channel and call numbers.

members join

Each developer runs ./install.sh --join-org <url> from their own gitzilla and gives the admin the fingerprint it prints. The admin approves it. From then on, that developer's pushes to the org are silent.

bound to you

A push note only counts for the member who signed it. Alice's note never silences a push made with Bob's account, so one stolen token can't hide behind a teammate.

who pushed

Every org alert has a Pusher: line. A push from an account that hasn't joined is orange. A force-push without its pusher's note is red and rings the on-call phones, even from a bot or the web UI.

clear next step

Every alert ends with the same instruction: revoke tokens at github.com/settings/applications. Anyone who sees it knows what to tell the account owner.

Setup

# phone: install ntfy, then subscribe to the topic the installer prints
# slack: create an incoming webhook for the channel
#        (Slack → Apps → Incoming Webhooks → Add to channel), copy its URL
# calls: ntfy Pro, verify the numbers in ntfy, create an access token (tk_…)

$ ./install.sh                         # the worker step asks for Slack, numbers and token (hidden)
$ bin/notify-test                      # one test alert to every channel; rings at most once an hour

# organizations
$ ./install.sh --org acme              # admin: org Worker, app and profile org-acme
$ ./install.sh --join-org <url>        # each member, the admin included
$ GITZILLA_PROFILE=org-acme bin/org approve <login> <fingerprint>
  • The Slack URL, ntfy topic, phone numbers and call token are stored only as Worker secrets, sent on stdin. They never touch your disk or logs.
  • Anyone who knows the ntfy topic can read the alerts. Share it only with people who should see them.
  • Anyone can ask to join under any login. Approve only a fingerprint the member gave you directly.
  • Alerts in a shared channel show repo names, private ones included. Use a channel limited to the right people.
